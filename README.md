# 記帳本

一個給自己用的記帳網頁 App。跟一般記帳 App 不同的地方是它以**先規劃、再花錢**為主軸：

1. 每個月先把薪水**分配到各個帳戶**（生活費、房租、儲蓄、投資…），實際轉完帳就打勾。
2. 指定其中一個帳戶當**零用錢來源**，App 自動算出**每天可以花多少**。
3. 首頁像熱量 App 一樣，一眼看到「今天還能花多少」。

## 功能

- **薪水分配** — 每月收入拆到各項目，逐筆勾選「已轉帳」，未分配金額即時提示。
  設定過一次之後，**之後每個月自動沿用**（打勾狀態會清空），改動才會存成該月專屬的
- **分配項目自己定義** — 名稱自己取（房貸、學貸、旅遊基金…），並指定類型：
  日常零用錢 / 固定支出 / 儲蓄 / 投資 / 其他，以及**這筆錢放在哪個存放處**。
  可在分配頁當場新增，點名稱即可改；清單依類型分組並顯示各組小計
- **現金與戶頭分開算** — 「存放處」是錢實際放的地方（錢包現金、各家戶頭）。
  新增時先選現金或戶頭，再從**台灣銀行／電子支付清單**挑一個（可用名稱或三碼代碼搜尋），
  名稱、圖示與品牌色會自動帶入；清單裡沒有的也能自己輸入。
  零用錢可以拆成現金一部分、戶頭一部分，記帳時選這筆從哪裡付，
  就能分別得出「錢包還剩多少」和「戶頭還剩多少」
- **每日零用錢** — 由零用錢帳戶自動推算，也可以手動指定；支援**結餘累積**（今天沒花完，明天可以繼續花）
- **快速記帳** — 依 日期 → 金額 → 分類 → 付款來源 → 說明／照片 的順序填。
  計算機式數字鍵盤支援 `+` `−` 直接算（分帳、湊發票好用），分類與付款來源會自動帶入上次用的
- **明細頁看的是零用錢結餘** — 收入每月就是薪水，沒有看的價值，所以版面留給
  「零用錢還剩多少」和「本月支出」，並列出各存放處的餘額
- **詳細說明與照片** — 每筆可寫多行說明（吃了什麼、在哪買的），並附上照片（發票、餐點）。
  照片會自動壓縮後存進 IndexedDB，明細列表直接顯示縮圖
- **明細** — 依日期分組、每日小計，可搜尋、篩選，點一下就能修改或刪除
- **統計** — 每日支出長條圖（標出超過額度的日子）、分類佔比排行、近 6 期比較
- **自訂** — 帳戶與分類都可以自己增刪改（圖示、顏色）
- **記帳週期** — 可設定每月起算日，發薪日不是 1 號也能對齊
- **深色模式** — 跟隨系統或手動切換
- **PWA** — 手機「加入主畫面」後就像原生 App，離線也能開
- **版本更新** — 改版之後手機不會自己換新版（PWA 的殼是 cache-first）。
  偵測到新版會在首頁跳一條「有新版本了 · 立即更新」，
  「設定 → 版本」也能看目前跑的版本、手動按「檢查有沒有新版本」

## 雲端同步（選用）

「設定 → 雲端同步」可以把資料存進一個 GitHub repo。設定頁提供兩個選項：

- **用這個 repo** — 帳號與 repo 名稱直接從網址讀出來，不用另外開，只要貼 token。
  資料進 `data/`，而且 `data/**` 不會觸發部署，記帳不會一直重建網頁。
  代價是這個 repo 是公開的（免費帳號的 Pages 只能從公開 repo 發佈），帳目也就公開
- **另開一個 repo** — 資料放進獨立的 Private repo，帳目不公開。程式仍留在公開 repo，
  兩者互不影響：瀏覽器是拿 token 走 API 讀寫資料，跟 Pages 無關

不論選哪一種：

- 手機和電腦連同一個 repo 就是同一份資料
- 記錄有變動會自動上傳（延遲數秒），開啟或切回 App 時會自動下載
- 每次同步都是一次 commit，改錯或誤刪可以從 GitHub 的歷史紀錄復原
- 兩邊改到**同一個月份**時才會停下來問你留哪一邊，不會默默覆蓋
- 同步一開，**手動備份的提醒就會停掉** — 每次記帳都自動上傳，比每週匯出一次可靠。
  只有同步壞掉或卡在衝突時，提醒才會再跳出來

需要一組 [fine-grained token](https://github.com/settings/personal-access-tokens/new)，
只給那個 repo 的 Contents 讀寫權限即可。Token 只存在瀏覽器本機，
不會寫進 repo，也不會出現在匯出的備份檔裡。

> ⚠️ 存進**公開** repo 的話，帳目所有人都看得到。要私密就另開一個 Private repo。

### 資料長什麼樣

不是一包大 JSON，而是拆成一個月一個檔的 markdown，人看得懂、`git diff` 也乾淨：

```
data/meta.md               設定、存放處、分配項目、分類
data/months/2026-08.md     該月的薪水分配 ＋ 所有記錄
data/photos/<id>.jpg       照片
```

```markdown
---
month: "2026-08"
income: 72000
rollover: true
---

## 分配

- {"accountId":"a1","amount":30000,"done":true}

## 記錄

- {"id":"t1","type":"expense","amount":320,"categoryId":"c1","walletId":"w1","note":"滷肉飯","date":"2026-08-16"}
```

分檔的好處是**同步以檔案為單位**：手機改八月、電腦改七月，兩邊各自上傳、自動合併，
不會因為動到同一包資料就互相蓋掉。

## 資料存在哪

本機這份永遠是主體，UI 只讀寫它：

- 記錄、分類、帳戶、每月計畫 → `localStorage`
- 照片 → `IndexedDB`（一張手機照片好幾 MB，localStorage 全部只有 ~5MB 放不下）

雲端同步不是另一種儲存後端，而是疊在本機之上：把本機這份推上去、把別台的拉下來。
**沒開同步的話，手機和電腦各自是獨立的一本帳**，搬資料要用「設定 → 資料備份 → 匯出／匯入」。
備份檔含照片，所以照片多的話檔案會偏大。設定頁也會顯示目前用掉多少空間。

清除瀏覽器資料會連記錄一起清掉。開了同步就不用擔心這件事；沒開就要定期匯出。

> ⚠️ iPhone 上「主畫面 App」和 Safari 是兩個獨立的儲存空間，資料不互通，
> 刪掉主畫面圖示會把那一份一起刪掉。兩邊都連同步才會是同一本帳。

## 開發

```bash
npm install
npm run dev      # 本機開發
npm run build    # 產出 dist/
npm run preview  # 預覽 build 結果
```

## 部署

推到 `main` 或任何 `claude/*` 分支就會自動經由 GitHub Actions 部署到 GitHub Pages。

第一次使用需要先到 **Settings → Pages → Build and deployment → Source** 選擇 **GitHub Actions**。

網址會是 `https://<帳號>.github.io/accounting-book/`。

版本號由 build 時的 commit 自動產生（`日期-短 sha`），同時寫進 JS 與 `sw.js` 的 cache 名稱，
**不需要手動 +1**。改前端忘了改版本號 → 瀏覽器看不出 service worker 有變 → 手機永遠停在舊版，
這個坑用衍生版本號直接消掉。
